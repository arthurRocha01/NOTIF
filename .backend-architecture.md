# Backend Architecture — NOTIF

## Stack

- **Framework:** NestJS 11 (Express adapter)
- **Language:** TypeScript 5.7
- **ORM:** Prisma 6 → MySQL
- **Auth:** JWT (Passport.js) + bcrypt
- **Docs:** Swagger em `/api`

---

## Estrutura

```
backend/src/
├── main.ts                  # Bootstrap + Swagger
├── app.module.ts            # Root module
└── modules/
    ├── auth/                # Autenticação JWT
    ├── users/               # Gestão de usuários
    ├── sectors/             # Setores/unidades
    ├── notifications/       # Notificações
    └── assignments/         # Atribuições usuário ↔ notificação
```

Cada módulo segue a mesma divisão em camadas:

```
[módulo]/
├── application/     # Services (regras de negócio)
├── domain/          # Entidades com comportamento
├── infrastructure/  # Repositórios + Mappers (Prisma)
└── presentation/    # Controllers (HTTP)
```

---

## Banco de Dados

```
Sector ──< User ──< NotificationAssignment >── Notification
```

| Tabela                   | Campos-chave                                                  |
|--------------------------|---------------------------------------------------------------|
| `sectors`                | id, name (unique)                                             |
| `users`                  | id, name, email (unique), passwordHash, role, sectorId, fcmToken |
| `notifications`          | id, title, message, level, slaMinutes, sectorId (null=global), authorId |
| `notification_assignments` | id, userId, notificationId, status, dueAt, deliveredAt, viewedAt, acknowledgedAt |

**Enums:**
- `UserRole`: `EMPLOYEE` · `SUPERVISOR` · `ADMIN`
- `NotificationLevel`: `LOW` · `MEDIUM` · `HIGH` · `CRITICAL`
- `AssignmentStatus`: `PENDING` → `VIEWED` → `ACKNOWLEDGED` / `OVERDUE`

---

## Fluxo de Autenticação

```
POST /auth/login (email + password)
  → AuthService.validateUser()  [busca user, compara bcrypt]
  → JWT gerado { sub: userId, email }  [expira em 1h]
  → retorna { access_token }
```

Rotas protegidas usam `@UseGuards(JwtAuthGuard)`.  
Secret: variável `JWT_SECRET` (fallback inseguro hardcoded — **trocar em produção**).

## Endpoints

| Método | Rota                    | Descrição                  |
|--------|-------------------------|----------------------------|
| POST   | /auth/login             | Login → JWT                |
| GET/POST/PATCH/DELETE | /users        | CRUD de usuários           |
| GET    | /users/by-email/:email  | Busca por e-mail           |
| GET/POST/PATCH/DELETE | /sectors      | CRUD de setores            |
| GET/POST/PATCH/DELETE | /notifications | CRUD de notificações      |
| GET/POST/DELETE       | /assignments  | Atribuições (sem update)   |
| GET    | /                       | Health check               |

---

## Ciclo de Vida de uma Notificação

```
Criada → Atribuída (Assignment PENDING)
       → Entregue   (deliveredAt + dueAt calculado pelo SLA)
       → Visualizada (VIEWED)
       → Confirmada  (ACKNOWLEDGED)
         ou Vencida  (OVERDUE se dueAt < now)
```

- `CRITICAL` + não `ACKNOWLEDGED` → `isBlocking() = true`
- `sectorId = null` na notificação → notificação global (todos os setores)

## Padrões Aplicados

- **Repository Pattern** — abstração de dados via interface (`IUserRepository`, etc.)
- **Mapper Pattern** — conversão domínio ↔ persistência
- **DTO Pattern** — contratos de API com validação (`class-validator`)
- **Clean Architecture** — presentation → application → domain → infrastructure

## Pontos de Atenção

- `JWT_SECRET` tem fallback hardcoded; definir em `.env` antes de ir para produção.
- `passwordHash` é nullable no schema — permite usuários sem senha (auth híbrida futura?).
- `fcmToken` (Firebase Cloud Messaging) está presente no backend em produção mas ausente no código local — campo obrigatório em `POST /users` e retornado no `GET /users/by-email/:email`.
- Endpoint de update de assignments está comentado — funcionalidade incompleta.
- `AssignmentsInteractionService` existe mas parece incompleto (transições de estado manuais).
- `.env` commitado com credenciais de dev — não commitar em produção.
