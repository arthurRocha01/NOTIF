# Frontend Architecture — NOTIF

## Stack

- **Framework:** Flutter (Dart 3.2+)
- **State Management:** Riverpod 2.5 (`StateNotifierProvider`)
- **HTTP:** `http` package + `ApiClient` próprio
- **Roteamento:** `go_router` 17.1 (incluso mas **não ativo**)
- **Storage local:** `shared_preferences` (incluso mas **não usado**)
- **Charts:** `fl_chart` | **Icons:** `lucide_icons` | **Fonts:** `google_fonts`

---

## Estrutura

```
lib/
├── main.dart                  # Bootstrap + ProviderScope
├── core/
│   ├── api/                   # ApiClient (HTTP client estático)
│   ├── constants/             # Cores, espaçamentos, radius, durações
│   ├── model/                 # UserModel (entidade compartilhada)
│   ├── theme/                 # Material 3 theme
│   └── utils/                 # Formatadores de data, helpers responsivos
├── features/                  # Módulos por feature
│   ├── login/                 # Tela de login + AuthNotifier
│   ├── home/                  # Shell do app + feed de posts
│   ├── alerts/                # Alertas (admin e usuário)
│   ├── dashboard/             # Painel de monitoramento
│   ├── profile/               # Perfil e conta
│   └── notices/               # Avisos/documentos
└── shared/
    ├── layout/                # AppDrawer
    └── widgets/               # Componentes reutilizáveis
```

Cada feature segue o padrão:
```
[feature]/
├── screens/       # Widgets de tela
├── providers/     # Riverpod state + Notifiers
├── services/      # Chamadas à API
├── models/        # Modelos + enums
└── widgets/       # Widgets específicos da feature
```

## Navegação

Não usa `go_router`. A navegação é feita manualmente via `IndexedStack` no `HomeScreen`:

```
LoginScreen (não ativado no main — bypassa auth para dev)
  └── HomeScreen (entry point atual)
        ├── [0] FeedContent       — feed social de posts
        ├── [1] DashboardScreen   — monitoramento
        └── [2] AlertAdminScreen  (Supervisor)
              AlertUserScreen     (Employee)
```

Bottom nav adapta-se ao role do usuário. Drawer acessa `AccountScreen` e modais auxiliares.

## Estado (Riverpod)

| Provider | Tipo | Estado |
|---|---|---|
| `authProvider` | `StateNotifierProvider` | `UserModel?` (null = deslogado) |
| `alertProvider` | `StateNotifierProvider` | `AlertState` (listas + loading flags) |
| `dashboardProvider` | `Provider` (computed) | `DashboardData` derivado de `alertProvider` |
| `profileProvider` | `StateNotifierProvider` | Avatar + display name local |
| `feedProvider` | `ChangeNotifierProvider` | Posts + página ativa |

## Integração com API

**Base URL:** `https://api.notif.com.br/v1` (prod) / `http://localhost:3000` (dev)

**ApiClient** (`/core/api/api_client.dart`) — classe estática com:
- Métodos: `get`, `post`, `patch`, `delete`
- Injeta `Authorization: Bearer <token>` automaticamente
- Lança `ApiException(message, statusCode)` em erros

**Serviços por feature:**

| Serviço | Endpoints usados |
|---|---|
| `AuthService` | `POST /auth/login`, `GET /users/email/{email}` |
| `AlertService` | `GET /alerts/active`, `GET /alerts/history`, `POST /alerts`, `PATCH /alerts/{id}/resolve` |
| `PostService` | Mock em memória (sem API real) |

---

## Fluxo de Autenticação

```
LoginScreen
  → AuthService.login(email, password)   → POST /auth/login → JWT
  → ApiClient.setToken(token)            → armazenado em memória (estático)
  → AuthService.fetchUser(email, token)  → GET /users/email/{email}
  → state = UserModel                    → authProvider atualizado
```

**Problema:** token fica só em memória — perdido ao reiniciar o app.  
`shared_preferences` está no pubspec mas não integrado ao fluxo de auth.

## Pontos de Atenção

- **Login não redireciona** — `main.dart` mostra `HomeScreen` diretamente (TODO no código).
- **Token não persiste** — sessão perdida ao reiniciar; `SharedPreferences` não integrado.
- **`go_router` não ativo** — sem deep linking nem rotas nomeadas.
- **Feed de posts é mock** — `PostService` não consome API real.
- **Sem testes** — nenhum arquivo de teste encontrado no frontend.
- **Dashboard parcialmente mockado** — `dashboardProvider` deriva dados locais de alertas, não de endpoint dedicado.
